## Decisions Made

- **Default move = period + capital sentence**, not semicolon: semicolons read like em dashes to readers (RESEARCH.md guideline 3). Used colons only where the second clause defines/specifies the first.
- **Parens used sparingly** — only when the aside contained internal commas (clipify's q_transcribe list, daytrade's `BaseStrategy` list, nfl-predict's tutorial shape, etc.) so a comma pair would have created list ambiguity.
- **Middot for decorative separators** because `ContactSection.astro` already used `&middot;` between GITHUB/LINKEDIN/RESUME — picking middot keeps the typographic system internally consistent.
- **One rewrite per fenced-code-aside dash needed a connector rather than parens** (daytrade `check_signal_on_df` — shared indicator math, shared entry logic — so any drift...). Recast as a participial phrase: "sharing indicator math and entry logic, so any drift..." This preserved the load-bearing claim without parenthesizing an aside that the rest of the sentence depends on.
