## Typography

Fixed ramp of MASTER §3 role classes only. Every text element uses exactly one role class — no ad-hoc sizes/weights/line-heights.

| Role | Class | Size | Weight | Line Height | Use in this phase |
|------|-------|------|--------|-------------|-------------------|
| Display | `.display` | clamp(4rem, 9vw, 8rem) | 700 | 0.92 | NOT USED (homepage hero only) |
| Section heading | `.h1-section` | clamp(2.5rem, 5vw, 3.5rem) | 600 | 1.05 | NOT USED this phase |
| Project title | `.h2-project` | 1.75rem | 500 | 1.2 | WorkRow title — **both tiers**, unchanged (`--ink`) |
| Lead | `.lead` | clamp(1.25rem, 2vw, 1.625rem) | 400 | 1.4 | NOT USED for the tagline (see rationale below) |
| Body | `.body` | 1.125rem | 400 | 1.6 (max 68ch) | **Featured-row tagline line** (`--ink-muted`) — the single tier-distinguishing field (D-08) |
| Label (mono) | `.label-mono` | 0.75rem | 500 | uppercase, ls 0.12em | `SectionHeader` label; `FEATURED` / `MORE WORK` tier sub-labels; Home "See all work →" link |
| Meta (mono) | `.meta-mono` | 0.8125rem | 400 | ls 0.02em | WorkRow number, year (`.tabular`); stack line (0.8125rem mono uppercase 0.12em — the `.work-stack` selector override, MASTER §5.5) |

**Tagline type-role rationale (SC5 / frontend-design call):** MASTER §3 offers `.lead` and `.body` as the two prose roles. Phase 22's *single* featured hero block used `.lead` for its summary and it read well with room to breathe. Here the featured tier is **three stacked rows**, not one hero — a `.lead` tagline (up to 1.625rem) would sit within ~0.13rem of the 1.75rem `.h2-project` title and, repeated three times, dissolve the title's dominance and the "list" quality. The enrichment signal the featured tier needs is the **presence** of an extra content line (rest rows have none — D-08), not a size contest with the title. Therefore the tagline renders at `.body` (1.125rem) in `--ink-muted`, producing a clean three-step ladder per row: `--ink` 1.75rem/500 title → `--ink-muted` 1.125rem/400 tagline → `--ink-faint` 0.8125rem mono stack. `.body`'s 68ch max-width naturally caps line length; the ≤80-char tagline (D-06) stays one line at desktop.

`.tabular` (tabular-nums) applies to the number and year columns per MASTER §3.3 (unchanged).

The ENTIRE palette is MASTER §2.1's six hex tokens. No new colors, no `oklch`, no gradients, no rgba, no dark theme (MASTER §2.3 lock). No card backgrounds, shadows, or border-radius (MASTER §8 — editorial numbered rows only).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAF7` `--bg` | Page background — `/projects` and Home |
| Text (30%) | `#0A0A0A` `--ink` / `#52525B` `--ink-muted` / `#A1A1AA` `--ink-faint` | Titles `--ink`; **featured tagline** + WorkRow number `--ink-muted`; stack, year, section count, `FEATURED`/`MORE WORK` labels `--ink-faint` |
| Surface / dividers (30%) | `#E4E4E7` `--rule` | WorkRow `border-bottom`, section rule, tier-divider trailing hairline |
| Accent (10%) | `#E63946` `--accent` | See reserved list below |
| Destructive | not applicable | No destructive actions in this phase |

Accent reserved for (MASTER §7 signal rule — "if a user can't click it, it can't be accent"):
- WorkRow hover/focus title underline + arrow reveal — **both tiers** (existing `WorkRow.astro`, unchanged)
- Home "See all work →" link hover (color→accent + arrow opacity reveal, mirroring `.read-more`)
- Focus rings on every interactive row and the "See all work" link (`outline: 2px solid var(--accent); outline-offset: 2px`)
- Homepage wordmark trailing dot (`.accent-dot`, existing — not this phase's work)

Accent NEVER on (MASTER §7.2): the **featured tagline text** (`--ink-muted`, never accent — it is not separately clickable), the `FEATURED` / `MORE WORK` tier labels, the tier-divider hairlines (`--rule` owns those), stack/year meta, body text, any surface fill/banner/panel. The tagline sits inside the row anchor but takes **no** hover color change — only the title carries the accent affordance, so the row keeps a single, unambiguous signal.

## Interaction & Component Contract (phase-specific)

Reuse-over-invention. This phase does **not** create a new listing grammar — it partitions the existing numbered `WorkRow` list into two tiers and adds one content line to the top tier.

### Two-tier structure (`/projects`) — D-07/D-08/D-09

One `§ 01 — WORK` `SectionHeader` (count `7 / 7`), then, in order:

```
§ 01 — WORK                                        7 / 7
──────────────────────────────────────────────────────  (SectionHeader rule)

FEATURED ──────────────────────────────────────────────  (tier sub-label + hairline)
  01   SeatWatch                                    2026
       <tagline .body --ink-muted>
       STACK · STACK · STACK
  02   Multi-Chain EVM Trader                       2026
       <tagline>
       STACK · STACK · STACK
  03   NFL Prediction                               2025
       <tagline>
       STACK · STACK · STACK

MORE WORK ─────────────────────────────────────────────  (tier sub-label + hairline, 48px above)
  04   SolSniper                                    2025
       STACK · STACK · STACK
  05   Optimize-AI                                  2025
  06   Clipify                                      2024
  07   DayTrade                                     2024
```

- **Numbering is continuous 01→07** across both tiers, mapping directly to the `order` field (D-11: seatwatch=1 … daytrade=7). Keeps the numbered-ledger grammar honest (MASTER §5.5) and the count truthful. Featured = 01/02/03, rest = 04/05/06/07.
- **Tier divider form** (frontend-design call, mirrors Phase 22 `earlier-divider` exactly): a flex row — `.label-mono` label (`--ink-faint`, `flex: 0 0 auto`) + `gap: 12px` + a `1px` `--rule` hairline (`flex: 1 1 auto`) filling the remaining width. `FEATURED` sits directly under the SectionHeader rule (tight top gap); `MORE WORK` opens the tier break with `margin-top: 48px`. Both sub-labels are quieter than the ink `§ 01 — WORK` header and carry the inline hairline, so they read as sub-tier markers, never as duplicate section headers. Both groups are labeled (not just the split) so the asymmetry is legible in a 30-second scan.

### Featured-row form — D-08 (frontend-design call)

The featured row is the existing `WorkRow` with **one added line**. Body column order becomes: `title` (`.h2-project`, `--ink`) → **`tagline`** (`.body`, `--ink-muted`) → `stack` (mono, `--ink-faint`). Meta column (year + hover arrow) unchanged. Vertical rhythm inside the body column: title `margin-bottom: 8px` (to tagline), tagline `margin-bottom: 12px` (to stack). Row `padding: 28px 0` and the `56px 1fr auto` grid hold unchanged — the row simply grows taller by one line. Rest rows are the current `WorkRow` verbatim (no tagline; title `margin-bottom: 12px` to stack, per the primitive today).

### Component shape (builder discretion — recommended)

**Recommended: extend `WorkRow.astro` with an optional `tagline?: string` prop.** When present, render the tagline `<p class="body work-tagline">` between title and stack; when absent, the row is byte-identical to today. Rationale: reuse-over-invention, one primitive, and **one row treatment everywhere** (D-12/D-14) — `/projects` featured tier and Home both call the same extended `WorkRow`. A sibling `FeaturedRow.astro` primitive is an allowed alternative (D-63 discretion); either way the visual contract above (placement, `.body`/`--ink-muted`, 8/12px rhythm) is binding. The primitive lives in `src/components/primitives/` with scoped `<style>`, no Tailwind utilities (MASTER convention). Adding an optional prop is a sanctioned extension of MASTER §5.5, not a spec revision.

### Home work list — D-13/D-14

Home keeps the **3-featured teaser** (the `featured` partition sorted by `order` → SeatWatch/Multi-Chain/NFL = 01/02/03), NOT featured-then-rest, preserving the punchy 30-second scan. Each featured row uses the **same** extended treatment as `/projects` (tagline present — D-14). After the work-list, add a `See all work →` link to `/projects`, mirroring the ABOUT section's existing `.read-more` idiom (`.label-mono`, `display: inline-block`, `margin-top: 24px`, `--ink-muted` default → `--accent` hover, arrow reveal). Update the SectionHeader count to `3 / 7`.

### Data derivation — D-12

Both pages derive from the same pipeline: `getCollection("projects")` → partition by the `featured` boolean → sort each tier by `order`. `/projects` renders both tiers; Home renders only the featured partition + the "See all work" link. No schema change (`featured` + `order` already in `src/content.config.ts`).

### Interaction states (MASTER-locked)

- **Hover / focus (both tiers):** existing `WorkRow` contract — title gets the accent underline (`text-decoration-color: var(--accent)`, 1.5px, offset 4px); arrow fades in (opacity 0→1, 120ms) and slides 4px right (180ms ease-out, MOTN-03). The **tagline takes no hover change**. Focus ring `outline: 2px solid var(--accent); outline-offset: 2px`.
- **"See all work →" link:** color→accent (120ms) + arrow opacity reveal (120ms), no translate. Focus ring as above.
- **Reduced motion:** existing paired override in `WorkRow.astro` and the `.read-more`-style link — arrow reveal/slide neutralized, the accent color/underline (sub-200ms color change, MASTER §6.2) remains as the affordance.
- **No scroll-triggered animation, no entrance animation** on the tier reveal or the featured rows (MASTER §8; MOTION.md governs only the root cross-document fade).

### Chat-surface invariant (SC5 / D-17)

Prefer **page-scoped `<style>`** on `projects.astro` / `index.astro` (and the primitive's scoped style) over `global.css`. If `global.css` or `BaseLayout.astro` is touched, run the D-26 chat-surface battery and hold the D-15 SSE byte-identical anchor. Nav is untouched this phase, so chat-surface risk is low unless a shared file is edited. `pnpm exec astro check` stays 0/0/0.
