### Persistence — KV Write Path (KV-)

- [x] **KV-01** — Cloudflare KV namespace `CHAT_KV` bound on production + preview; declared in `wrangler.jsonc kv_namespaces`. Distinct from auto-injected `SESSION` binding.
- [x] **KV-02** — `src/lib/chat-transcripts.ts` provides pure `appendTurn(kv, sessionId, role, content, meta)`. Key naming `live:{sessionId}`. Schema versioned `v: 1`. `expirationTtl: 30 * 24 * 3600` on every `put()`.
- [x] **KV-03** — KV `metadata` field carries `{ last_activity_at, msg_count }` so cron `list({prefix:'live:'})` filters without per-key `get()`. O(n) round-trips eliminated.
- [x] **KV-04** — Transcript values bounded: 30-turn cap; `referrer` / `user_agent` truncated to 512 chars. Worst-case value size well under KV's 25 MiB ceiling.
- [x] **KV-05** — Per-sessionId write quota tracked inline in KV `metadata` as `{ window_started_at, window_count }`. Hard cap 100 writes per sessionId per rolling 1-hour window. Overflow → silent log + skip per D-09 posture. Race policy: last-writer-wins per D-13.

### Identity — sessionId (IDENT-)

- [x] **IDENT-01** — Client mints sessionId via `crypto.randomUUID()` on first chat open. Persisted in localStorage with `STORAGE_VERSION` bumped 1→2 (existing auto-clear path triggers). Sent in `/api/chat` request body.
- [x] **IDENT-02** — Server validates sessionId as UUIDv4 in `src/lib/validation.ts` (`z.uuidv4().optional()`). **Missing-tolerance branch (D-04 amendment):** absent sessionId is acceptable — server skips `ctx.waitUntil(appendTurn(...))` and still serves the SSE stream. Present-but-malformed → 400. **sessionId NEVER threaded into the Anthropic message payload** — preserves prompt cache hit rate.

- [x] **CRON-01** — `wrangler.jsonc triggers.crons: ["0 * * * *"]` (hourly). Worker `scheduled()` handler delegates to `deliverDue(env)` via `ctx.waitUntil(...).catch(...)` rejection-safe pattern (Phase 18 D-09).
- [x] **CRON-02** — `src/lib/chat-delivery.ts deliverDue` lists `prefix: "live:"` with cursor pagination; filters via `metadata.last_activity_at < now - 2h`. - [x] **CRON-03** — Per-session try/catch isolates failures; per-tick batch cap 50; send-attempt counter cap 3 retries; pagination hard-cap 50 pages; structured JSON logs per tick (`sessions_seen`, `sessions_due`, `sessions_promoted`, `errors`).

### Email Delivery — Resend Integration (MAIL-)

- [x] **MAIL-01** — `src/lib/email/resend.ts` thin `fetch()` wrapper to `https://api.resend.com/emails` (REST not SDK — zero new runtime deps; `package.json dependencies` byte-identical phase-wide). `Authorization: Bearer ${RESEND_API_KEY}`. `Idempotency-Key: transcript/{sessionId}` header on every POST. - [x] **MAIL-02** — Email body is plaintext only — Resend `text` field, no `html` field. Block format: `>>> visitor:` / `<<< bot:` markers per turn. - [x] **MAIL-03** — Every dynamic field (user content, bot content, referrer, user-agent, country) HTML-escaped at render time even though body is plaintext. CR/LF stripped from all header components. Unicode bidi overrides (`U+202A..U+202E`, `U+2066..U+2069` + LRM/RLM/ALM marks) stripped from all dynamic fields.
- [x] **MAIL-04** — Email subject server-controlled `[Portfolio chat] N turns from <country> via <referrer-host>`. From `transcripts@mail.jackcutrara.com`. Reply-To `jackcutrara@gmail.com`. To `jackcutrara@gmail.com` via `CHAT_RECIPIENT_EMAIL` Wrangler secret.

## Out of Scope (explicit exclusions at milestone planning)

- Admin UI / dashboard / list view of transcripts — Jack reads every email in entirety
- Transcript search / aggregation / NLP summarization — same anchor
- AI summarization of transcripts — defeats the purpose of reading them
- Conditional emailing (≥3 turns) — Jack wants every conversation
- D1 / SQL persistence — KV is right shape; no aggregation need
- Resend npm SDK — REST via `fetch()` avoids Node-runtime deps in Workers
- Cloudflare Email Sending service — public beta only since 2026-04-16, no deliverability track record
- MailChannels — free Workers tier ended 2024-08-31 (dead path)
- Per-token KV writes — exceeds KV's 1 write/sec/key cap
- Server-issued cookie sessionId — client-mint preserves localStorage compatibility
- Cross-device session continuation — corner case, no clear value
- Multi-tab session merging — last-write-wins acceptable
- HTML rendering of user-typed text — phishing-into-inbox surface
- Markdown rendering / auto-linkification of user input in email — same surface
- Push notifications / Slack / SMS delivery — email sufficient at portfolio scale
- Cron interval shorter than 1 hour — locked
- Inactivity threshold other than 2 hours — locked
- Encryption-at-rest for transcripts — KV is encrypted at rest by default; YAGNI
- Visitor disclosure of logging in chat UI — silent logging chosen
- Recruiter-vs-visitor classification — site traffic low enough that Jack reads everything
